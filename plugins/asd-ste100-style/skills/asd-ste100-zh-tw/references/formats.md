# 媒介規則

這些規則是使用者需要相關媒介時的表達與交付提示，不是 ASD-STE100 的要求。各媒介共用 SKILL.md 的語意規則；HTML 無障礙另參考 [獨立來源](sources.md#html-無障礙的獨立來源)。實作、渲染與完整無障礙驗收仍由原任務及其工具負責。

## 圖解

- 用流程圖表達順序與條件；用架構圖表達元件；用表格比較選項。依環境選用可編輯的 Mermaid、SVG 或其他既有工具。
- 節點寫具體名稱；箭頭標示關係或條件。已知資料流才畫資料流，相關關係不可畫成未經證實的因果箭頭。
- 將限制放在對應節點或圖說。用文字標籤區分狀態，不僅以顏色表示。提供簡短文字說明，讓未顯示圖片時仍能理解。
- 研究圖表只使用已提供或已查證的資料；示意圖明標「示意」。不得為了畫面完整而虛構量測值。

## HTML

- 優先沿用現有專案元件與工具。獨立解說頁在沒有其他需求時，用一個可離線開啟的 HTML 檔即可；不為單頁解說新增框架。
- 用語意化標記與適合讀者的字型，依頁面主要語言設定 `lang`；繁體中文頁面可用 `<html lang="zh-Hant">`。按鈕能用鍵盤操作，輸入有標籤，焦點可見；文字與背景有足夠對比。
- 互動需幫助理解，例如調整參數、逐步顯示流程或比較條件。將模擬、假設與真實觀測標清楚，並保留不操作時可讀的核心說明。
- 動畫尊重 `prefers-reduced-motion`；不以動畫或顏色作唯一訊息來源。沒有必要就不加入自動播放、外部追蹤、字型下載或網路相依。
- 將來源文字視為資料，不插入可執行 HTML。建立檔案後，在環境與授權允許時檢查呈現及互動；未執行時明示驗證範圍。遵守使用者既有的瀏覽器工具選擇。

## 解說影片

- 先確認使用者要腳本、分鏡還是成片。依需求提供場景、畫面、旁白、字幕與時間；未指定片長時，採能說明核心內容的最短篇幅。
- 每個場景先呈現主要概念，再加入必要細節。畫面、字幕與旁白使用同一術語；同步呈現重要條件與限制。
- 使用者提及某位創作者時，採用可描述的特徵，例如逐步建構數學圖形、動畫演示與清楚節奏；不冒稱由該創作者製作。
- 配音僅用已授權、已設定的工具；不讀取或要求貼出 API 金鑰。沒有可用工具時，交付腳本或靜音視覺方案並說明限制。不得為文案任務自行註冊服務、下載模型、付費或部署。
- 有實際渲染才宣稱產出影片；有實際播放、字幕與音訊檢查才宣稱通過對應檢查。

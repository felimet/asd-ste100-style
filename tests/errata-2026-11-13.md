# 勘誤（2026-11-13）

## 第二組 protocol 的鎖定雜湊對應的是 CRLF 工作目錄檔案

[eval/heldout2-protocol.md](eval/heldout2-protocol.md) 第 7 行列出的鎖定雜湊是作者 Windows 工作目錄（`core.autocrlf=true`，檔案為 CRLF）的 sha256：

| 檔案 | protocol 列出的值（CRLF 工作目錄檔案） | git blob（LF）的 sha256 |
| --- | --- | --- |
| `eval/heldout2-prompts.json` | `c90206947a092a90cf21694a190bdfe8c66d5a7fff1052edbbc366d563893b0f` | `fcd9b83942070a4d73a21c8c00d1e241510d9796d5d9086b9737e63e19d0d7d3` |
| `eval/heldout2-gold.json` | `bfcd58b36e65c4786a520526db136dabcdc9ea51ebcbb2161e9d51582ecfc185` | `6bc85857edb227e5ad6ccfe4ae85863a492fb877a5028d851201bebfbd450f1f` |

把 git blob 的換行換成 CRLF 後，sha256 與 protocol 列出的值相同（2026-11-13 驗證），所以內容沒有變，只是從 git 取出的檔案要先轉成 CRLF 才對得上。這不影響第二組的結論。

第三組的鎖定檔（`eval/heldout3-prompts.json`、`eval/heldout3-gold.json`、`eval/heldout3-probes.json`、`eval/triggers2.json`）已在 `.gitattributes` 設為 `text eol=lf`，工作目錄與 blob 都是 LF，雜湊直接等於 protocol 列出的值。

日期：2026-11-09。原始回覆、逐題評審與觸發紀錄見 [cli-eval-2026-11-09.json](cli-eval-2026-11-09.json)；題目與執行程式見 [eval/](eval/)。

## 設計

- 生成者與評審者各用兩個 CLI：
  - agy 1.5.3，模型 `gemini-4-argon-medium`。
  - Codex CLI 0.166.0，reasoning effort `medium`，關閉 memories 與 hooks。
- 5 個臂：`base`（不載入 skill）、`old`（commit 85ac56d）、`v110`（1.1.0）、`v111`（1.1.0 加兩條規則：限定篇幅只交付符合限制的答案；使用者表達挫折時先用一句話承接）、`lean`（v111 再把文件與操作指引移到 `references/documents.md`；即 1.1.1）。
- 21 題（`eval/prompts.json`）。每題預先列出必備要點（atoms）與非 LLM 機械檢查（必含字串、首末行、字數上限、純 JSON）。
- 交叉盲評：每個 CLI 都評兩個生成者的回覆，標籤順序依題號旋轉。評審給 atoms、directness、readability、tone、是否捏造。機械檢查與字數、條列比例由程式從儲存的回覆重算。
- 每臂每題一次取樣。結果可由 `python tests/eval/run_cli_eval.py selftest` 驗證統計程式，完整流程見 `eval/run_cli_eval.py` 開頭說明。

## 結論

- 選 `lean`（1.1.1）：agy 端 atoms 與機械檢查最高；Codex 端 atoms 與 base 相當（0.964 對 0.965）、機械檢查低於 old（0.905 對 0.952，差在 p20 首行承接）。主檔從 11.5 KB 縮到 9.6 KB；文件類題目（p07、p12、p13）在兩個 CLI 都有讀取 `references/documents.md`，非文件題（p05）沒有讀，atoms 無退步。
- 效益只在 agy 量到（readability 與 tone 高於 base，字數減少約一半）。Codex 端各臂與 base 的 atoms 差距都在 CI 內，這份資料沒有顯示 skill 對 Codex 有可量測的好處。
- 只有 agy 的 lean 對 v110 的 atoms 差距 CI 不跨 0，下限 0.005，量級很小。

## 限制

- n = 21、每臂單次取樣；atoms 在多數題目達上限，只有少數題目能分出臂間差距。
- p06、p15、p17 至 p21 是針對 v111 的兩條新規則自擬的題目，不是獨立保留題。v110 到 lean 的差距多數來自這幾題；其餘題目只顯示沒有退步。
- 評審與生成者是同兩個模型家族。兩個 CLI 都載入使用者的全域 AGENTS.md（約 10 KB），對所有臂相同，但可能壓低 Codex 對 skill 的反應；p04（使用者固定第一行）在 Codex 所有臂都失敗，來源是該全域指令，不是 skill。
- 「捏造」旗標幾乎全來自 Codex 評審對 agy 回覆的判斷（v110 4 筆、lean 7 筆、v111 8 筆、base 20 筆）；單一評審、n = 21，差距未驗證。
- `skill_read` 欄由工具呼叫紀錄推得，只供參考。
- `agy plugin install`、一行 GitHub 安裝與 always-on rule 載入沒有在這次測試。

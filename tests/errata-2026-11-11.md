# 評測紀錄勘誤（2026-11-11）

本檔更正 `cli-eval-2026-11-09.md` 與 `heldout-eval-2026-11-10.md` 的錯誤與未揭露的偏差。原紀錄不改。下列數字由 2026-11-11 的審查發現，再以 `tests/eval/run_cli_eval.py` 的函式從兩份 JSON 重算確認。

## 更正

- `cli-eval-2026-11-09.md` 結論第一點寫文件類題目「atoms 無退步」，第 61 行寫其餘題目「只顯示沒有退步」，兩處都不精確。p07 的 agy lean 為 0.875，base、v110、v111 都是 1.0；這是 agy lean 全部 21 題中唯一失分的一題。lean 回覆的刪除前檢查用不加 `-i` 或 `-v` 的 `rsync -n`，內容不一致時也不會輸出，閘門無法否證。base 也寫了同樣的靜默檢查，但另有 SHA-256 比對作為最後閘門，所以這個錯誤不能歸因於 skill。
- `heldout-eval-2026-11-10.md` 寫 h05「三個臂都最低」，與該檔逐題資料不符：base 最低的是 h09（0.688），h08（0.775）也低於 h05（0.781）。lean 在 h05 的低分主要來自 Codex 評審：Codex 生成的 lean 回覆，agy 評審判 7/8 個 atoms 成立，Codex 評審只判 1/8。
- `heldout-eval-2026-11-10.md` 第 42 行用「載入 SKILL.md」欄推論「載入率較高但 atoms 沒有提高」，這個推論不成立。舊的 `skill_read` 會把任何 SKILL.md（包括其他全域 skill）與本 skill 資料夾內的任何檔案都算成載入，例如 Codex base 臂 h07 rep0 沒有安裝本 skill，卻記為 True；agy 的斜線呼叫也可能不經工具讀檔就套用 skill。harness 已改為只比對本 skill 的 SKILL.md 路徑，reference 另外記錄。

## 未揭露的偏差

- 整段重複：agy 常把同一份答案完整輸出兩次，而且不載入 skill 時更常發生。保留題 base 15/20、v110 7/20、lean 5/20；2026-11-09 的 agy base 7/21、lean 2/21。Codex 都是 0。評審與字數都使用重複後的文字，所以 agy 端的字數差距與可讀性差距有一部分來自重複率，不完全是寫法的差異。
- 可讀性與長度：評審 rubric 的可讀性包含「沒有重複或贅述」。agy 端 lean − base 的逐題可讀性差（兩位評審平均）與字數對數差強烈負相關：2026-11-09 為 r = −0.808（21 題），保留題為 r = −0.914（10 題，兩次取樣平均），所以「可讀性提高」與「回覆縮短」不是兩項獨立證據。
- 開發題與範例重疊：選擇 lean 的正向差距來自 7 道針對新規則自擬的題目（p06、p15、p17 至 p21）。其餘 14 題的 lean − v110 atoms 差為 agy −0.0089、Codex +0.0000。p06 與 1.1.1 新增的情緒範例同型，p01 與範例「還不能說完成」同型。
- 評審一致性：保留題兩位評審在 atom 層級的一致率為 0.879，Cohen's κ 為 0.492。捏造旗標在 120 組配對中，69 組是 agy 判否、Codex 判是，兩位都判是的只有 4 組。所以捏造旗標應分評審報告，不宜合併解讀。
- 標籤順序：舊 harness 以雜湊從全部排列中挑一個順序，兩位評審看到相同順序，各臂出現在各位置的次數不平衡。harness 已改為依題號與評審循環輪替。
- 評測環境：所有臂都載入作者的全域指令檔；Codex 另外載入已啟用的 plugins 與 `~/.agents/skills` 下的全域 skill，agy 也執行作者的 hooks。base 臂因此不是「無任何指令」，結果不能推到未自訂設定的 Agent。
- 可重現性：v110 與 v111 的 SKILL.md 沒有提交到 repo，`heldout-protocol.md` 與結果在同一個 commit（6bdd122）加入，無法從版本紀錄確認判定規則先於結果。之後的評測由 harness 在 `arms.json` 記錄各臂檔案的 sha256，判定規則先單獨提交（見 `eval/heldout2-protocol.md`）。
